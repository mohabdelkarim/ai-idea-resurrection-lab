# Analysis: ActiveStorage: Allow access to backing file from Service API

> Add a `download_blob` method to ActiveStorage services to return raw file streams for flexible handling.

**Why it will work now:** Rails 6.1 added DiskService#path and signed_id features, enabling direct file access implementation.

---

## Why It Died

The issue required changes across all ActiveStorage service adapters, which were maintained by a small core team. At the time, Rails lacked a unified abstraction for streaming raw files, making implementation complex. Additionally, the community prioritized higher‑impact features like direct uploads and background analysis, leaving this enhancement unfunded.

## Why 2026 Changes Everything

Rails 6.1 introduced the DiskService#path method and signed_id support, providing a stable hook for raw file access. The rise of Ruby 3.2's Ractor model encourages thread‑safe IO handling, simplifying adapter implementations. Modern testing tools like RSpec's built‑in file fixtures make cross‑adapter verification easier.

## Modern Architecture

Introduce a new abstract method `download_blob(key)` in ActiveStorage::Service, returning an IO-like object. Implement default behavior in DiskService using `File.open(path, 'rb')`. For cloud services, wrap the SDK's streaming download (e.g., AWS SDK's `get_object` with `response_target: io`). Add a thin adapter layer that yields a `ActiveStorage::Service::File` wrapper exposing `read`, `size`, and `close`. Update the Service::UrlGenerator to optionally delegate to `download_blob` when a signed URL is not desired. Ensure all adapters conform to the new interface via shared RSpec examples, and document the method in the API guide.
