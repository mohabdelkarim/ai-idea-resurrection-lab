## Why It Died

The core PromQL engine was deliberately kept simple, and changing rate/increase required a deep rewrite of the query executor. At the time, the TSDB lacked efficient per‑sample interpolation primitives, making a correct implementation costly. Maintainers prioritized stability and performance over a non‑critical feature, and the issue received little community traction. Additionally, the lack of a formal specification for extrapolation led to divergent opinions on the correct algorithm. Consequently the proposal stalled and the issue was closed without action.

## Why 2026 Changes Everything

Prometheus 2.40 introduced native subquery support and improved range‑vector handling, providing a solid foundation for custom extrapolation. The OpenMetrics specification now defines explicit rules for counter resets and interpolation, removing previous ambiguity. Go 1.21 added generics and improved profiling tools, enabling a clean, type‑safe implementation without runtime overhead. Recent advances in the Prometheus TSDB, such as block‑level index caching, make per‑sample calculations feasible at scale. These concrete changes collectively eliminate the technical blockers that existed in 2018.

## Modern Architecture

Introduce an Extrapolator interface with methods EstimateRate and EstimateIncrease, implemented by a LinearExtrapolator class. Extend the existing QueryEngine to accept an optional Extrapolator, defaulting to the legacy behavior for backward compatibility. The LinearExtrapolator will read raw samples from the TSDB block reader, apply a weighted linear regression over the configurable window, and emit confidence intervals. Configuration flags (e.g., --extrapolation.window) allow operators to tune the window size per metric. The new module will be registered via a plugin system, enabling future strategies such as spline or Bayesian extrapolation without core changes. Comprehensive unit tests and benchmark suites will validate accuracy against recorded rules, and documentation will guide users on enabling the feature in Grafana dashboards.
