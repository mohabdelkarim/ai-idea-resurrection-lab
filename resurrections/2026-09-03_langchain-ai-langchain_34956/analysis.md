## Why It Died

The original proposal lacked a unified observability framework within LangChain, making metric export cumbersome. Maintainers prioritized core model integration over dashboard features, limiting bandwidth for such extensions. Existing LangSmith tooling was considered sufficient, so external metric pipelines received low priority. Additionally, the absence of a standard telemetry SDK in Python at the time hindered straightforward implementation.

## Why 2026 Changes Everything

OpenTelemetry SDK 1.24, released in early 2026, provides a standardized API for real-time metric collection and export. LangChain v0.2 introduced an extensible CallbackManager that can hook into agent execution events. The Python async ecosystem has matured, allowing non-blocking metric emission. These tools together remove previous technical barriers, enabling seamless dashboard integration.

## Modern Architecture

Introduce a MetricsExporter class that implements the OpenTelemetry MeterProvider interface and registers counters for latency and token usage. Extend the existing CallbackHandler to emit events to the MetricsExporter during each agent step, preserving async compatibility. Provide a configuration object in LangChain settings to select exporter backends such as Prometheus, Datadog, or custom HTTP endpoints. Leverage the new CallbackManager's pluggable architecture to allow users to inject additional exporters without modifying core code. Ensure thread-safe metric updates using Python's asyncio locks and expose a simple start/stop lifecycle tied to the LangChain runtime.
