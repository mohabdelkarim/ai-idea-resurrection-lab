# Analysis: Load scrape configs from multiple files

> Prometheus can now load scrape configurations from multiple separate files using a glob pattern.

**Why it will work now:** Go 1.21's improved embed.FS and filesystem APIs enable dynamic config file loading.

---

## Why It Died

The core team prioritized other critical features and lacked bandwidth to redesign the config parser. Existing reload logic was tightly coupled to a single file, making safe multi-file support risky. Concerns about backward compatibility and validation complexity delayed implementation.

## Why 2026 Changes Everything

Go 1.21 introduced embed.FS enhancements and the io/fs package now supports glob patterns directly, simplifying dynamic file loading. Prometheus' modular reload architecture has been refactored since 2024, exposing clearer hooks for config extensions. The new yaml.v3 library offers better streaming parsing, reducing memory overhead for multiple files.

## Modern Architecture

Introduce a ScrapeConfigLoader struct that accepts a slice of glob patterns and resolves them using fs.Glob. The loader reads each file into a yaml.Node, validates uniqueness of job_name across all sources, and merges the resulting slice into the existing ScrapeConfig slice. Integrate the loader into the existing ConfigReloader via a new LoadScrapeConfigs method, which returns an error on duplicate names or parse failures, preserving the atomic reload semantics. Update the main configuration struct to include a ScrapeConfigFiles []string field, annotated for yaml unmarshalling. Add unit tests covering glob expansion, duplicate detection, and error propagation. Document the feature in the official configuration guide with examples.
