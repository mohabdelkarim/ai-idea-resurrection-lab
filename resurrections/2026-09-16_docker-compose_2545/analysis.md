# Analysis: Proposal: support for args_file

> Docker Compose should support an args_file option to load build arguments from external files.

**Why it will work now:** Docker BuildKit and secret management APIs introduced in Docker 18.09 enable secure args_file handling.

---

## Why It Died

When the issue was opened, Docker Compose lacked a modular parser to ingest arbitrary file formats during the build phase. The original implementation would have required significant changes to the YAML loader, which the core team prioritized elsewhere. Additionally, secret handling was not yet standardized, making the security benefits unclear. Community bandwidth was limited, and there was no consensus on the best syntax for argument files. Consequently, the proposal stalled and never progressed.

## Why 2026 Changes Everything

Docker BuildKit, introduced in Docker 18.09, provides a robust API for passing secret files to the build context, eliminating earlier security concerns. Docker Compose v2, rewritten in Go, now includes a pluggable configuration system that can easily map new keys like args_file. The official CLI flag --secret and the underlying libcompose library expose structured access to external argument files. These tools together make implementing args_file straightforward and safe. Moreover, the rise of supply-chain security tooling encourages explicit secret management in CI pipelines.

## Modern Architecture

Add a new ArgsFile struct within the service configuration model, mirroring the existing EnvFile implementation. Extend the Go parser in libcompose to recognize the args_file key and resolve relative paths based on the compose file location. During the build step, read each file line-by-line, parse VAR=VAL pairs, and merge them into the service's BuildArgs map, respecting precedence over explicit args entries. Leverage the BuildKit client API to inject these arguments as secret files, using the existing secret handling pipeline. Update the command execution path to pass the aggregated arguments to the Docker daemon via the BuildKit client. Provide unit tests for file parsing, precedence logic, and integration tests using a local Docker daemon with BuildKit enabled. Finally, extend the documentation generator to include the args_file section with examples.
