# RFC: Enable Messages PII Anonymization through External APIs

1. Summary
LangChain will introduce a first‑class PII anonymization layer that can be plugged into any agent or chain via the existing callback manager. The feature is delivered as an `AnonymizerCallback` handler that forwards each message to a configurable external API (e.g., OpenAI's new PII‑filtering endpoint) using an `ExternalAnonymizerClient` built on httpx. The handler sanitizes the content before it reaches logging, storage, or user‑visible output, providing a low‑overhead, opt‑in privacy safeguard for developers.

2. Motivation
Recent regulatory pressure and corporate privacy policies require that user‑provided data never be persisted in raw form. While LangChain already supports callbacks for tracing and monitoring, it lacks a standardized hook for content sanitization. Earlier attempts failed because:
- No unified callback interface existed.
- External PII filters were scarce or unreliable.
- Latency concerns discouraged integration.
Since the 0.1.20 release introduced a robust `CallbackManager`, and OpenAI now offers a dedicated PII‑filtering endpoint with sub‑100 ms latency, the ecosystem now supports a clean, performant implementation. Providing this capability out‑of‑the‑box will reduce duplicated effort across the community and make LangChain a safer default for production deployments.

3. Detailed Design
**3.1 Core Classes**
- `AnonymizerCallback(BaseCallbackHandler)`: Implements `process_message(message: AgentMessage) -> AgentMessage`. It extracts `message.content`, calls `ExternalAnonymizerClient.anonymize(text)`, replaces the content, and forwards the modified message downstream.
- `ExternalAnonymizerClient`: Wrapper around httpx with configurable `base_url`, `api_key`, `timeout`, and `retry` policy. Provides both `async_anonymize` and `sync_anonymize` methods returning the sanitized string.

**3.2 Configuration**
Add a new section to `langchain.settings.Settings`:
```python
class Settings(BaseSettings):
    anonymizer_endpoint: str = "https://api.openai.com/v1/pii/filter"
    anonymizer_api_key: str = ""
    anonymizer_timeout: float = 2.0
    anonymizer_retry_attempts: int = 3
    anonymizer_redaction_rules: List[str] = []  # optional custom patterns
```
Developers enable the callback by:
```python
from langchain.callbacks import CallbackManager
from langchain.anonymizer import AnonymizerCallback

cb = CallbackManager([AnonymizerCallback()])
agent = Agent(..., callbacks=cb)
```

**3.3 Integration Points**
The callback is inserted early in the stack so that every `AgentMessage` (user, AI, tool) passes through it before any other handlers (e.g., logging, tracing). The sanitized message is then emitted to downstream callbacks unchanged.

4. Drawbacks
- **Latency**: Even with fast endpoints, an extra HTTP round‑trip adds latency; high‑throughput use‑cases may need batch processing or local filters.
- **Dependency on External Service**: Outages or rate‑limits of the PII API could block message flow unless fallback logic is added.
- **Cost**: Some providers charge per‑call; users must be aware of potential expenses.
- **Complexity**: Introducing another callback may increase the learning curve for newcomers.

5. Alternatives
- **Local Regex‑Based Redaction**: Implement a pure‑Python filter using regexes. This avoids network calls but is brittle and hard to keep up with evolving PII definitions.
- **Middleware Layer**: Instead of a callback, add a separate middleware pipeline before agents. This would require a larger architectural change and duplicate existing callback functionality.
- **Third‑Party SDK Integration**: Wrap existing SDKs (e.g., AWS Comprehend) directly in the agent code. This approach scatters privacy logic across projects rather than providing a unified LangChain feature.

6. Unresolved Questions
- Should the callback support batch anonymization for multi‑message streams to amortize latency?
- How should authentication failures be surfaced to the user (exception vs. silent pass‑through)?
- Will we need a fallback to a local redaction rule set if the external service is unavailable?
- What is the optimal default retry/back‑off strategy to balance latency and reliability?
- Are there any legal implications of sending raw user data to third‑party services that need explicit consent handling?
