## Why It Died

The core maintainers prioritized security and feature parity over debugging utilities, leaving little bandwidth for small additions. Requests lacks a standardized __repr__ for raw HTTP messages, making a generic printer ambiguous. Community contributions were sparse, and the issue lingered without a clear owner, causing it to fade.

## Why 2026 Changes Everything

The Rich library (2020) provides easy console rendering of styled text, simplifying pretty‑printing of HTTP messages. Python f‑strings and dataclasses (3.7+) allow concise, readable formatting of request and response attributes. Enhanced Response.raw handling in recent releases gives direct access to the original HTTP payload, enabling accurate reconstruction.

## Modern Architecture

Introduce two functions, print_request and print_response, in requests.utils. Each function accepts an optional 'style' flag; when True, they use Rich's Console to render colored headers and bodies, otherwise fall back to plain text. Internally, they build a dataclass representation of the HTTP message to separate formatting logic from the core request/response objects. Add unit tests covering both styled and plain outputs, and update the documentation with examples. Ensure backward compatibility by keeping the functions optional and not importing Rich unless the style flag is used.
