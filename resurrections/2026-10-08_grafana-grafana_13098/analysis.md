# Analysis: [Feature] Row collapse status in URL

> Add URL parameters to preserve row collapse state when sharing Grafana dashboards.

**Why it will work now:** Grafana 9 added unified URL state handling, enabling persistence of row collapse status in shared links.

## Why It Died

The feature required deep integration with Grafana's URL state serialization, which lacked a stable API in 2018. At that time, the dashboard rendering pipeline was not modular enough to expose row collapse state externally. The core team prioritized other roadmap items, and limited contributor bandwidth prevented implementing the necessary changes. Additionally, there were concerns about URL length limits and backward compatibility with older Grafana versions.

## Why 2026 Changes Everything

Grafana 9 introduced a unified URL state management system that cleanly serializes panel and row states. The new "state" package provides APIs to read and write arbitrary UI states via query parameters. Improvements in Go's net/url handling and the adoption of the "go-chi" router simplify parsing complex URL structures. These advancements remove previous technical blockers, making row collapse persistence feasible.

## Modern Architecture

Implement a new URLStateHandler struct within the dashboard package that registers a "rowCollapse" key. Extend the existing DashboardState model to include a map of row IDs to boolean collapse values. During dashboard rendering, the UI component reads this map and sets each row's initial collapsed property. When a user toggles a row, the handler updates the map and triggers a URL sync via the state.SyncToURL method. Ensure backward compatibility by falling back to default collapse behavior when the parameter is absent. Add unit tests for serialization/deserialization and update documentation to describe the new URL parameter.
