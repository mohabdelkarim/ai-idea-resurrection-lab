# Analysis: Support multiple --exec <cmd> instances

> Add an option to fd that prints each matched path alongside each executed command.

**Why it will work now:** Rust's stable std::process::Command enhancements in 2023 enable richer exec handling.

## Why It Died

The maintainer prioritized core performance improvements over UI enhancements, leaving limited time for new flag implementations. fd's internal exec handling lacked a straightforward way to expose the matched path to the user, requiring a substantial refactor. Community contributions were sparse, and the feature was not deemed critical for the majority of users at the time.

## Why 2026 Changes Everything

Rust 1.73 introduced stable Command::env_remove and improved handling of current working directories, simplifying per-execution path injection. The walkdir crate now provides DirEntry::path() directly in its iterator, allowing easy access to matched paths. clap v4 supports multiple occurrences of the same flag with custom validators, enabling clean syntax for repeated --exec specifications.

## Modern Architecture

Introduce an ExecSpec struct containing the command template and a placeholder for the matched path. Extend the CLI parser (clap) to accept multiple --exec flags, each constructing an ExecSpec instance. Modify the core runner to iterate over matched entries, rendering each ExecSpec by substituting the placeholder with the entry's path before spawning the process via std::process::Command. Add an optional --print-path flag that, when enabled, logs the path prior to command execution using the log crate. Ensure backward compatibility by keeping the original single --exec behavior when only one ExecSpec is provided.
