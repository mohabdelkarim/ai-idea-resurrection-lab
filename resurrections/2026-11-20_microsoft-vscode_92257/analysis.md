# Analysis: Markdown Preview - Navigate back

> Add back navigation support within VSCode Markdown preview to return to the previous preview page.

**Why it will work now:** Webview API enhancements in VSCode 1.85 enable custom navigation handling.

## Why It Died

The original issue lacked a stable API to intercept link clicks inside the Markdown preview webview, making it hard to implement custom back navigation. Performance concerns about adding another navigation stack in the preview were raised by the core team. Additionally, the feature was low priority compared to other editor enhancements, resulting in limited community bandwidth to address it.

## Why 2026 Changes Everything

VSCode 1.85 introduced an enhanced Webview API with bidirectional messaging and a navigation history service. The new "vscode-webview-ui-toolkit" provides reusable components for handling user interactions within previews. Command registration now supports context-aware actions, allowing the preview to expose its own navigateBack command without affecting the editor's history.

## Modern Architecture

Implement a PreviewNavigationManager class in the markdown extension that maintains a stack of visited preview URIs. Extend the markdown preview webview to emit a custom event on link activation, pushing the target URI onto the stack. Register a new command "markdown.preview.navigateBack" that pops the stack and updates the webview source. Integrate this command with the existing workbench navigation service so that Backspace and Mouse4 trigger the preview-specific back action when the preview is focused. Ensure the manager synchronizes with the global navigation history to avoid conflicts, and add unit tests covering stack operations and command execution. Update the extension's contribution points to expose the new command and keybinding, and document the behavior in the Markdown extension README.
