# Analysis: Named hooks: MVP support

> Introduce a useDebugName hook to provide explicit names for custom React hooks in DevTools.

**Why it will work now:** React 18’s new DevTools hook inspection API enables attaching metadata to hooks.

---

## Why It Died

The core React runtime had no mechanism to attach arbitrary metadata to hook calls, making the proposal difficult to implement. DevTools developers prioritized performance and stability over UI niceties, leaving little bandwidth for experimental features. Parsing source maps to infer names proved brittle and was deemed a temporary workaround. Community interest waned as newer debugging tools emerged, and the issue lost momentum.

## Why 2026 Changes Everything

React 18 introduced a DevTools hook inspection API that allows fibers to expose custom debug information. The Fiber architecture now includes a HookDebugInfo field that can carry arbitrary strings. Modern TypeScript compiler APIs and Babel 7 plugins make automated source‑code transforms trivial. These tools together enable a reliable, low‑overhead way to attach names to hooks.

## Modern Architecture

Add a new no‑op hook called useDebugName that records the provided string in a HookDebugInfo structure attached to the current fiber. Extend the Fiber class with an optional debugInfo property holding a map of hook indices to names. DevTools reads this map via the existing hook inspection channel and displays the names in the component tree. Provide an optional Babel plugin that automatically inserts useDebugName calls using the function's identifier, falling back to manual annotation when desired. Ensure the implementation is gated behind a feature flag and includes unit tests for the Fiber extension and the DevTools renderer integration.
