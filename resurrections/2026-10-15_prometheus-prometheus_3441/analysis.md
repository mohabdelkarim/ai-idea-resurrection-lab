# Analysis: Prometheus docker container shouldn't run as user nobody

> Allow the Prometheus Docker image to run with a configurable non‑root user ID.

## Why It Died

The change was introduced in Prometheus 2.0 without a configurable UID option, and the maintainers prioritized other core features. Community contributions were limited, and the Dockerfile simplicity was favored over added complexity. Additionally, security guidelines at the time accepted running as the generic "nobody" user, reducing perceived urgency.

## Why 2026 Changes Everything

Modern Docker supports build‑time ARGs and runtime environment variables to set the USER dynamically, enabling flexible UID/GID assignment. The official Dockerfile best practices now encourage non‑root containers with configurable users. Go's os/user package and init scripts have improved for handling dynamic user creation inside containers.

## Modern Architecture

Introduce an optional environment variable, e.g., PROMETHEUS_UID and PROMETHEUS_GID, parsed at container start. In the entrypoint script, if these variables are set, use 'adduser' to create a dedicated user with the specified IDs and switch to it before launching Prometheus. Update the Dockerfile to accept build‑time ARGs for default UID/GID and set the USER directive accordingly. Ensure the Go binary runs under this user without assuming UID 99. Add unit tests for the entrypoint logic and update documentation to describe the new configuration options.
