# Analysis: Feature Request: Create a node's automatic node labels on its pods 

> Kubernetes will automatically copy selected node labels onto each pod it schedules.

**Why it will work now:** Admission webhook enhancements and CRI v1.2 now enable automatic node‑label propagation to pods.

---

## Why It Died

The proposal required deep changes to the kubelet and scheduler APIs, which were not stable in early Kubernetes versions. Community concerns about security implications of exposing node metadata to pods slowed adoption. Limited maintainer bandwidth and competing priority features caused the effort to stall.

## Why 2026 Changes Everything

Kubernetes 1.26 introduced robust Admission Webhook v1 APIs and the NodeLabelPropagation feature gate, enabling safe label copying. The CRI v1.2 spec now supports passing node label information to the container runtime. Enhanced kubelet configuration options allow selective propagation of node labels to pods.

## Modern Architecture

Implement a new Admission webhook that intercepts Pod creation requests, reads configured node label keys, and injects them into the Pod's metadata. The webhook respects a feature gate (NodeLabelPropagation) and a pod-level annotation to opt‑in. Extend the scheduler to cache allowed label keys per node for efficient lookup. Update kubelet to expose an API for the webhook to query node labels securely. Add a ConfigMap to define which node labels are propagatable, allowing cluster operators to customize behavior without code changes.
