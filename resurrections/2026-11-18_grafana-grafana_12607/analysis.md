## Why It Died

The feature relied on undocumented Chrome DevTools commands that were unstable in 2018, and Grafana's architecture lacked a headless browser integration layer. Community contributors prioritized other high‑impact features, leaving this request without sufficient development bandwidth.

## Why 2026 Changes Everything

Chrome DevTools Protocol now provides a stable headless screenshot API accessible via the go‑chrome‑dp library. Grafana's plugin SDK has been modernized to allow server‑side Go plugins to spawn headless Chromium instances. Additionally, the go‑chromedp and go‑rod packages simplify browser automation, making full‑page capture feasible within Grafana's backend.

## Modern Architecture

Introduce a ScreenshotService struct in the backend that uses go‑chromedp to launch a headless Chromium instance. The service receives a dashboard URL and rendering options, then navigates to the page, waits for panel rendering, and invokes the Page.captureScreenshot command with fullPage:true. Results are streamed back as PNG bytes and stored in Grafana's existing image cache. Expose a new HTTP endpoint /api/screenshot/fullpage that authenticates the request and calls ScreenshotService. Update the UI with a button that triggers the endpoint and displays the returned image. Ensure the service respects existing sandboxing and resource limits by reusing a singleton Chromium pool.
