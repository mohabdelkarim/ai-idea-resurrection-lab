# Analysis: Top navigation bar for multipage apps

> Streamlit should provide a top navigation bar widget for multipage applications.

**Why it will work now:** React 18 concurrent rendering and Streamlit's 2024 component API enable topbar implementation.

---

## Why It Died

The core Streamlit team prioritized stability and existing sidebar features, leaving little bandwidth for new layout widgets. Implementing a top bar required a redesign of the internal layout engine, which was deemed too risky without a dedicated maintainer. The lack of a unified theming API at the time made consistent styling across custom components difficult. Community contributions were limited, and the issue lost momentum as other features took precedence. Consequently the proposal was shelved.

## Why 2026 Changes Everything

Streamlit 1.30 introduced a version‑2 component API that simplifies custom React integration. React 18's concurrent rendering model provides smoother UI updates for dynamic top bars. CSS custom properties and Streamlit's new theming system allow consistent styling across widgets. The unified layout manager now supports multiple horizontal containers, enabling a top navigation region. These tools collectively remove the technical blockers that existed in 2019.

## Modern Architecture

Introduce a TopBar class inheriting from Streamlit's BaseWidget, exposing a new st.topbar API. The frontend adds a React component named TopBarContainer that registers with the existing layout manager and renders into a horizontal slot above the main content. Props include button definitions, dropdown items, and optional icons, all passed via the component API. Session state synchronizes user interactions, allowing callbacks to update the app. Styling leverages Streamlit's theming context and CSS variables for dark/light mode support. The layout engine allocates a fixed height region, adjusting the main content pane dynamically. Documentation and tests cover rendering, interaction, and theming edge cases.
