## Why It Died

The original request lacked a bi‑directional communication layer between the frontend tabs component and Streamlit's backend, making state synchronization impossible. At the time, Streamlit's component API only supported one‑way data flow, preventing dynamic tab selection. Additionally, the core team prioritized other UI features and had limited bandwidth to implement a full session‑state integration for tabs.

## Why 2026 Changes Everything

Streamlit 1.30 introduced a bi‑directional component API that allows frontend events to update backend session state in real time. The underlying React 18 framework now supports hook‑based state management, simplifying event handling for UI elements. WebSocket enhancements in Streamlit's runtime provide low‑latency synchronization, making backend‑controlled tabs feasible.

## Modern Architecture

Implement a new Tabs component extending Streamlit's custom component base, exposing props such as default_selected and on_change. The component registers a JavaScript event listener that emits the selected tab index to the backend via the bi‑directional API. On the server side, a dedicated SessionState entry stores the current tab index, which is read during each rerun to render the correct active tab. The backend can also programmatically set the index by updating the SessionState entry, triggering a UI refresh. This design leverages Streamlit's existing component messaging protocol and integrates with the unified WebSocket channel for efficient state propagation. Tests cover event propagation, default selection, and programmatic updates, while documentation illustrates typical usage patterns.
