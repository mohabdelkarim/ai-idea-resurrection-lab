## Why It Died

The feature was blocked by limited integration between Docker Engine and Apple's new container runtime, which lacked a stable API. Compose maintainers also faced bandwidth constraints and prioritized core Compose features. Additionally, the Apple Container tool was still in early beta, making reliable support risky.

Docker Engine 24.0 introduced a stable API for the Apple Container runtime, allowing external tools to manage containers. Go 1.22 added improved embed.FS handling, simplifying binary distribution of the runtime. Docker Compose v2 now supports a pluggable engine architecture, enabling third‑party container backends like Apple’s tool.
