# Analysis: Fiber Principles: Contributing To Fiber

> This issue proposes documenting internal Fiber design patterns for future contributors.

**Why it will work now:** The introduction of React 18 concurrent features and the new Scheduler API enable clearer Fiber documentation.

---

## Why It Died

The core React team prioritized feature development over internal documentation, leaving little time for a comprehensive Fiber guide. Existing code comments were considered sufficient, so no dedicated effort was allocated. The lack of a stable public API for Fiber internals made exposing design patterns risky. Community contributors were uncertain about the correct format and location for such documentation.

## Why 2026 Changes Everything

React 18 introduced concurrent rendering and a Scheduler API that clarified Fiber's role, creating demand for formal documentation. The React DevTools now expose Fiber internals, providing a practical reference point. TypeScript definitions for Fiber have been added to the @types/react package, enabling typed examples. These tools together lower the barrier for writing accurate, maintainable documentation.

## Modern Architecture

Create a dedicated 'docs/fiber' directory containing markdown files generated from TypeScript interfaces. Define a FiberSchema class that mirrors the internal Fiber structure using exported types, allowing the docs to stay in sync with the codebase. Implement a script that traverses the Fiber tree using the singly linked list traversal pattern and outputs annotated diagrams. Use React's Scheduler API examples to illustrate concurrent behavior and commit phases. Integrate the documentation generation into the CI pipeline to ensure updates on each release. Provide a contribution guide that outlines the pattern of mutating fibers only in beginWork/completeWork and using switch‑based tag dispatch.
