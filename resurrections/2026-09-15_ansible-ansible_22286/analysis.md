## Why It Died

The proposal required changes to Ansible's core execution engine, which lacked a clean hook for early role termination. At the time, the meta module API was not extensible enough to support new directives without risking backward compatibility. Core maintainers prioritized stability and other feature work, leaving the idea unfunded. Additionally, limited testing infrastructure made validating early exit semantics difficult. Community interest was modest, so the effort never materialized.

## Why 2026 Changes Everything

Ansible 2.12 introduced the collection architecture and a plugin-based execution model, providing extensible hooks for meta plugins. The new "strategy" API allows custom control flow, making early role termination implementable without core rewrites. Enhanced test harnesses and CI pipelines now support granular role-level testing. Improved Python type hinting and static analysis tools simplify safe integration of new meta commands. These advances collectively remove the technical barriers that existed in 2017.

## Modern Architecture

Implement the end_role directive as a new MetaPlugin class extending the existing MetaBase. Register the plugin via the collection entry point, allowing it to be discovered without core changes. In the strategy layer, add a hook that checks for the end_role flag after each task and triggers a RoleTerminator exception. The exception propagates to the playbook executor, which gracefully skips remaining tasks in the current role while preserving play context. Update the YAML schema to include the new meta key, leveraging the existing schema validation framework. Provide unit tests using the ansible-test integration framework, mocking role execution to verify early exit behavior. Document the feature in the user guide and collection README, illustrating usage patterns and limitations.
