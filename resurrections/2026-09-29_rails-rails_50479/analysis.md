## Modern Architecture

Create a new multi‑stage Dockerfile that builds the Thruster Go binary in the first stage using the official golang:1.22 image. The final stage copies the binary into the official rails:8 image and sets an entrypoint script that launches Thruster before Puma. Thruster listens on port 443, terminates HTTP/2, and forwards requests to Puma via a Unix socket, preserving low latency. Environment variables control caching headers and X‑Sendfile activation, allowing developers to toggle features per deployment. Health checks are added to ensure both Thruster and Puma are healthy, and logs are unified under the Rails logger format. The design remains optional; existing Dockerfiles can continue to use Puma directly if the proxy is not desired.
