# RFC: Adding Catppuccin Bat Themes

1. Summary
Add official Catppuccin color themes to bat's built‑in theme collection. The change introduces a new `src/themes/catppuccin/` directory containing TOML theme definitions, extends the Theme loading logic to parse these files, registers them in the ThemeRegistry, and provides a `--theme-catppuccin` flag for selection. Build‑time embedding via `include_str!` ensures zero runtime cost.

2. Motivation
The current bat distribution ships only a handful of hand‑curated themes. Community members have repeatedly requested Catppuccin palettes because they are popular across editors and terminals. Previously, adding third‑party palettes required manual copying of TOML files into the user's config, a friction point that discouraged contributions. Since bat 0.23 introduced TOML‑based theme loading and Rust 1.73 enhanced `include_str!` for compile‑time asset embedding, the technical barrier is now minimal. Moreover, the `catppuccin` Rust crate provides ready‑made color definitions, allowing us to generate accurate theme files programmatically. Incorporating these themes upstream improves out‑of‑the‑box user experience, aligns bat with modern aesthetic trends, and demonstrates a reproducible process for future external palettes.

3. Detailed Design
* **File layout**: Create `src/themes/catppuccin/` with one TOML file per flavor (e.g., `latte.toml`, `frappe.toml`, `macchiato.toml`, `mocha.toml`). Each file follows bat's existing TOML schema (syntax, background, regular, etc.) and is generated from the `catppuccin` crate's color constants.
* **Theme struct extension**: No changes to the public `Theme` API are required; the existing `serde` deserialization will automatically handle the new files.
* **Registry integration**: In `src/theme_registry.rs`, add a lazy_static `HashMap<&'static str, Theme>` entry for each Catppuccin theme. Registration occurs in `ThemeRegistry::init()` which now iterates over `include_str!` assets located in the new directory.
* **Command‑line flag**: Extend `clap` definitions in `src/cli.rs` with `--theme-catppuccin <FLAVOR>` (values: latte, frappe, macchiato, mocha). The flag resolves to the corresponding entry in the registry; if omitted, the standard `--theme` flag continues to work.
* **Build script**: Update `build.rs` to copy the TOML files into `OUT_DIR` and generate a Rust source file that contains `pub const CATPPUCCIN_LATTE: &str = include_str!("../src/themes/catppuccin/latte.toml");` etc. This guarantees the assets are compiled into the binary with no runtime file I/O.
* **Testing**: Add integration tests under `tests/theme_catppuccin.rs` that invoke bat with each new theme on a sample source file and assert that the output contains expected ANSI color codes for known token types.
* **Documentation**: Revise `README.md` to list the new themes and usage examples. Add a `CONTRIBUTING.md` section describing how to generate additional palettes using the `catppuccin` crate, ensuring a repeatable upstream process.

4. Drawbacks
* **Binary size increase**: Embedding four additional TOML files (~2 KB total) will marginally increase the binary footprint.
* **Maintenance overhead**: Future updates to the Catppuccin palette will require synchronisation; however, the process is automated via the crate, reducing manual effort.
* **Potential theme clash**: Users may confuse the new `--theme-catppuccin` flag with the generic `--theme` flag; careful documentation is needed to avoid ambiguity.

5. Alternatives
* **External plugin**: Ship the themes as a separate crate (`bat-catppuccin`) that users can install and load via `--theme-file`. This avoids binary bloat but adds a dependency and extra installation steps.
* **User‑only config**: Encourage users to place the TOML files in `$HOME/.config/bat/themes`. This keeps the core binary unchanged but repeats the current friction that prompted the RFC.
* **Merge into existing theme list**: Add the Catppuccin palettes directly under the generic theme namespace, selectable via the normal `--theme` flag. This would eliminate a dedicated flag but would mix third‑party themes with official ones, making future curation harder.

6. Unresolved Questions
* Should the Catppuccin themes be advertised as “official” or “community‑maintained”? This affects branding and future contribution expectations.
* How often should we sync with upstream Catppuccin releases? A quarterly schedule could be sufficient, but we need a maintainer commitment.
* Do we need to provide a fallback for terminals that do not support true‑color? The current bat implementation already degrades gracefully, but explicit testing is required.
* Will the addition of a new flag require changes to existing shell completions? We need to regenerate completions for Bash, Zsh, Fish, and PowerShell.
