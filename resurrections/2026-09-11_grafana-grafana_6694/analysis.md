## Why It Died

The original request predated Grafana's stable plugin SDK, making custom datasource development cumbersome. At the time, Go client libraries for the Google Analytics Reporting API were immature and lacked first‑class OAuth2 support. Grafana maintainers prioritized core visualisation features over niche integrations, resulting in low community interest. Additionally, the GA API required complex authentication flows that were not well‑documented for Grafana plugins. Consequently, the issue stalled and was marked stale.

## Why 2026 Changes Everything

Grafana's Plugin SDK v2 now provides a streamlined backend datasource framework with built‑in authentication hooks. The official Go client library googleapis/google-analytics-data-go offers type‑safe access to the GA Reporting API v4. Go's oauth2 package simplifies token acquisition and refresh handling. Grafana's recent support for OAuth2 data sources enables secure credential storage. Together these tools make a robust GA integration feasible today.

## Modern Architecture

Implement a new datasource plugin package that satisfies the backend.DataSource interface. The plugin registers a query handler that translates Grafana query models into GA Reporting API request objects. Authentication is managed via Grafana's OAuth2 datasource config, storing refresh tokens securely. A thin service layer wraps the google-analytics-data-go client, handling pagination and rate‑limit back‑off. Results are normalized into Grafana's time‑series format and cached using the built‑in query cache. The plugin also exposes a health check endpoint to validate API connectivity. Documentation and unit tests leverage Grafana's plugin SDK testing utilities.
