## Why It Died

The request required deep changes to the Electron‑based workbench layout, which conflicted with existing tab management code. At the time, VSCode lacked a flexible UI extension point for repositioning core components. The core team prioritized performance and consistency across platforms, leaving limited bandwidth for such visual experiments. Community contributions were scarce because implementing the feature demanded intimate knowledge of the internal rendering pipeline.

## Why 2026 Changes Everything

Electron 30 introduced a stable API for custom title‑bar and workbench region manipulation, allowing UI elements to be repositioned without forking the core. The VSCode extension host now supports declarative layout contributions via the "contributions" manifest, enabling third‑party or built‑in UI tweaks. Additionally, the recent refactor to a modular CSS‑in‑JS system simplifies dynamic styling of the tab bar, making bottom placement feasible with minimal performance impact.

The TabBar component should reuse the existing TabRenderer class, adjusting its CSS grid placement via a themable class. Update the main workbench renderer to conditionally mount the TabBar in the bottom container based on the setting, ensuring accessibility hooks remain intact. Add unit tests for the layout service and integration tests for the setting UI. Document the feature in the settings reference and provide a migration guide for existing custom themes.
