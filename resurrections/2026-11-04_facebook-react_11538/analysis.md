## Why It Died

React 16's rendering pipeline lacked hooks to detect external DOM mutations, causing fragile assumptions about the DOM tree. The core team prioritized concurrent features over edge‑case browser integrations, leaving limited resources for this fix. Google Translate's DOM rewrites were considered a Chrome bug rather than a React responsibility, reducing community pressure. Existing tests did not cover such mutations, making regression risk high. Consequently the issue stalled and was never prioritized.

## Why 2026 Changes Everything

React 18 introduced concurrent rendering and a refined Fiber scheduler that can pause and resume work, allowing safe checks before DOM operations. The new MutationObserver API in modern browsers provides reliable detection of external DOM changes. React's useSyncExternalStore hook offers a pattern to synchronize external state without breaking the render cycle. Additionally, the React team now ships a dedicated error handling layer for commit-phase failures, making this resilience feasible.

## Modern Architecture

Implement a wrapper component around the root container that registers a MutationObserver to monitor external DOM changes. During the Fiber commit phase, compare the observed DOM state with React's virtual DOM expectations and defer removals if a mismatch is detected. Introduce a new internal API, scheduleSafeCommit, that queues DOM mutations as microtasks, ensuring they run after any external modifications. Leverage the existing error boundary mechanism to catch and recover from unexpected DOM errors, logging them for developers. Update the reconciler to use useSyncExternalStore‑style subscriptions for external DOM state, keeping the virtual DOM in sync without triggering redundant renders. Finally, provide a fallback path that gracefully skips the offending DOM operation and re‑renders the component tree, preserving UI consistency.
