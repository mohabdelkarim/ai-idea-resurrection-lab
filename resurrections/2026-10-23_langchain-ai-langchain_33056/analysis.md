## Why It Died

The proposal arrived when LangChain's core team was focused on stabilizing the LLM integration layer, leaving little bandwidth for extensive API redesign. Existing contributors lacked consensus on a unified schema for multimodal content, causing indecision. Performance concerns about parsing large structured objects in the runtime also discouraged adoption. Additionally, the community prioritized backward compatibility, making a breaking change to Document unattractive. These technical and social blockers led to the issue being dropped.

## Why 2026 Changes Everything

Since 2025, multimodal LLMs such as GPT-4V and Claude 3 Vision have demonstrated robust handling of images, tables, and formulas, creating demand for richer data models. LangChain 0.2 introduced a pluggable schema system and native support for Pydantic v2, simplifying complex model definitions. The new "langchain-schema" package provides utilities for hierarchical document structures, reducing implementation friction. These concrete tools directly enable the richer Document interface envisioned in the original request.

## Modern Architecture

Introduce a RichDocument class inheriting from BaseDocument, using Pydantic v2 for validation and serialization. Decompose content into MediaComponent, TableComponent, and FormulaComponent, each implementing a common ContentPart interface. Employ a factory pattern (ContentPartFactory) to instantiate appropriate components based on MIME type or file extension. Store components in a hierarchical tree allowing nested structures and citations. Provide adapters for existing parsers to emit RichDocument parts, preserving backward compatibility. Extend LangChain's retrieval pipelines to accept RichDocument and propagate content parts to LLM prompts via the new multimodal prompt builder. Document the API with autogenerated OpenAPI schemas and comprehensive unit tests.
