## Why It Died

The core Redis engine lacked a per-field TTL data structure, making implementation complex. Adding expiration to individual hash fields would require significant changes to the dict implementation and persistence format. At the time, developer resources were focused on other high‑priority features, and the community did not rally around this request. Consequently the issue stalled without a concrete design. The lack of a modular extension point also prevented incremental experimentation.

## Why 2026 Changes Everything

Redis Modules API, introduced in 2018 and matured in Redis 7.0, now allows custom data types and background timers. The server's lazy expiration mechanism has been generalized, enabling field‑level eviction logic. Improved RDB/AOF serialization supports additional metadata per hash entry. These tools collectively make per‑field expiration feasible without rewriting the core dict code.

Extend the existing dict implementation for hashes to store HashFieldMeta instead of raw strings. Implement a background timer task that scans hash fields with TTL and removes expired entries, reusing the server's lazy expiration framework. Update the RDB/AOF modules to serialize the expiration metadata alongside field values. Expose new commands HSETEX and HEXPIRE to set values with TTL, and modify existing HGET/HDEL to respect expiration. Provide a Redis Module example that demonstrates the same behavior for custom hash‑like types, allowing developers to adopt the pattern without core changes.
